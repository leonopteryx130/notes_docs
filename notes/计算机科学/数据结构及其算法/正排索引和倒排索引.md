# 正排索引和倒排索引

### 基本概念

正排索引（Forward Index）：以**文档**为中心。记录每个文档里面包含哪些单词。比如：查「文档 1」有什么内容。

倒排索引（Inverted Index）：以**单词**为中心。记录每个单词出现在哪些文档中。比如：查「苹果」这个词在文档 1、3、5 中出现过。

二者是「正」与「倒」的关系：正排是 `文档 → 词`，倒排是 `词 → 文档`。搜索引擎之所以叫「倒排」，就是相对正排把映射方向反过来了。

| | 正排索引 | 倒排索引 |
| --- | --- | --- |
| 键 | 文档 ID | 词（Term） |
| 值 | 该文档的词列表 | 包含该词的文档列表（倒排列表 / Posting List） |
| 擅长 | 已知文档，看它有哪些词（展示、摘要、相关性计算） | 已知关键词，快速找相关文档（检索） |
| 不擅长 | 按关键词搜全文（要扫全部文档） | 直接还原某篇文档的完整内容 |

### 倒排索引建立过程

典型步骤：

1. **分词（Tokenization）**：把标题/正文切成词，并做去停用词、大小写归一等预处理。
2. **建词典（Dictionary）**：收集全部不重复词，为每个词分配单词 ID。
3. **写倒排列表（Posting List）**：对每个词，记下出现过它的 DocID；工程里还可附带词频 TF、出现位置等，便于排序和短语检索。

分词后可以得到这 16 个关键词，倒排列表中记录的是哪些文档包含这个关键词：

</div>

例如查「跳槽」：倒排列表是 `0, 3`，对应标题里带「跳槽」的两篇；查「Facebook」：列表是 `0,1,2,3,4`，五篇全中。

多关键词查询时，对各自倒排列表做集合运算即可，例如：

- 「谷歌 AND 跳槽」→ 列表求交
- 「加盟 OR 跳槽」→ 列表求并
- 「Facebook NOT wave」→ 差集

正排索引在工程里常作为倒排的配套：倒排负责「找哪些文档」，正排负责「拿到文档原文/词袋」做打分、高亮和展示。

### 相似词扩展检索

纯倒排是**精确匹配**：查「跳槽」只能命中带「跳槽」的文档，带「加盟」「离开」的文档不会命中，即便意思接近。

工程上常把倒排和相似词结合起来，实现「查一个词 → 带上近义词 → 再倒排找文档」：

1. 对查询词做**相似词扩展**（同义词表，或用词向量找余弦相近的词）。
2. 把原词 + 相似词一起丢给倒排索引（相当于 OR 查询）。
3. 合并各词的倒排列表，得到候选文档，再排序。

例如查「跳槽」：倒排精确命中 Doc `0, 3`。若用词向量表示查询词，在向量空间中按余弦相似度取出近邻词（如「加盟」「离开」），再对其倒排列表求并（「加盟」`1,2,4`，「离开」`2`），即可召回语义相近、但不一定包含原查询词的文档。

也可以直接用**句向量 / 文档向量**做语义检索（ANN），不经过词级倒排；实务里更常见的是：倒排（含相似词扩展）做召回，向量检索补语义召回，再融合排序。

### 应用场景

- **搜索引擎 / 站内搜索**：关键词 → 候选文档，ES、Lucene、Solr 的核心结构就是倒排索引。
- **全文检索**：日志、文档库、Wiki、邮件按关键字快速定位。
- **推荐与广告召回（关键词侧）**：用倒排从海量物料里按标签/关键词粗召回。
- **近义 / 语义召回**：查询词扩展相似词后再倒排，或配合词向量检索「意思相近」的文档。

### 小结

正排回答「这篇文档有什么词」，倒排回答「这个词出现在哪些文档」。需要「相似意思也召回」时，用相似词扩展或词向量，把查询从精确词匹配扩展到语义相关文档。
